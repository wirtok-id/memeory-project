# FOLDER_STRUCTURE.md — Memeory Project Structure

> **Architecture:** Feature-first Clean Architecture  
> **Pattern:** BLoC + Repository + Domain  
> **Flutter Version:** 3.22+

---

## Philosophy

Memeory follows a **feature-first** organization with **Clean Architecture** layers inside each feature:

1. **Feature-first** — all code related to a feature lives in one folder
2. **Clean layers** — `presentation → domain → data` separation within each feature
3. **Shared/Core** — truly reusable code lives in `core/` or `shared/`
4. **Flat is better than deeply nested** — max 4 levels of nesting

## Key Architecture Notes

### Feature Module Structure

Each feature follows Clean Architecture:

```
feature_name/
├── data/           # Implementation details (datasources, models, repo impl)
├── domain/         # Business logic (entities, use cases, repo contracts)
└── presentation/   # UI (pages, widgets, blocs)
```

### Import Rules

```dart
// ✅ Correct: use package imports
import 'package:memeory/features/auth/domain/entities/auth_user.dart';

// ✅ Correct: relative imports within same feature
import '../widgets/search_bar_widget.dart';

// ❌ Avoid: relative imports across features
import '../../search/presentation/pages/search_page.dart';
```

### Barrel Files

Each major folder has a barrel `index.dart` for clean imports:

```dart
// features/search/search.dart
export 'data/repositories/search_repository_impl.dart';
export 'domain/usecases/search_memes.dart';
export 'presentation/bloc/search_bloc.dart';
export 'presentation/pages/search_page.dart';
```
